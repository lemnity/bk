# Рабочие отчёты и HTML-редактор писем — спецификация

Дата: 2026-10-27. Репозиторий: статический сайт (HTML + CSS + vanilla JS, без сборки и бэкенда).
Кабинет администратора — `admin*.html` / `*.html` со скриптами `admin-*.js`, состояние — `window.AdminStore`
(localStorage `tbdt_admin_v1` + BroadcastChannel).

## Цель

1. **Рабочие отчёты везде, где есть отчёты.** Любой отчёт из каталога (`reports.html`, ~150 строк `CATALOG`
   в `admin-reports.js`) открывается на `report.html?no=…`, строится по параметрам формы и выгружается.
   Кнопки-заглушки становятся рабочими. Отчёт бухгалтерии на `ledger.html` строится из живых данных.
2. **HTML-редактор email-писем** в конструкторе `admin-letter.js`: правка исходного HTML письма с живым
   предпросмотром, форматирование текста, переменные подстановки, выгрузка `.html`, тестовая отправка.

## Ограничения (Global Constraints)

- G1. Без сборки, без npm-зависимостей, без внешних скриптов. Plain `<script>`-файлы с IIFE и `"use strict"`,
  как существующие `admin-*.js`. Новые файлы подключаются с `?v=1`; при правке существующего файла его
  `?v=N` во всех `<script src>`/`<link href>` увеличивается на 1.
- G2. Визуальная система: только токены и компоненты из `admin.css` (см. `docs/admin-design-system.md`,
  создаётся в задаче 1). Никаких новых hex-цветов вне `:root`; новые классы — с префиксом модуля
  (`rv-`, `rdoc-`, `lt-`, `rep-`, `dlg-`). Фокус виден, контраст AA, интерактивные элементы — `<button>`/`<a>`.
- G3. Данные отчётов — детерминированные: одинаковые параметры → одинаковые строки (сидированный ГПСЧ,
  без `Math.random`/`Date.now` в генерации). Источник — `AdminStore.state` (EVENTS, TIERS, LEDGER, VENUES,
  RENTALS); то, чего в хранилище нет (операции продажи), генерируется движком из этих данных.
- G4. Параметры формы отчёта реально фильтруют данные: период (с/по), мероприятие, канал продажи,
  тип оплаты — если поле есть в форме отчёта.
- G5. Каждая выгрузка повторяет то, что на экране (одна модель данных для экрана, Word, Excel, CSV, печати).
- G6. Пустой результат — понятное пустое состояние «Нет данных за выбранный период», не пустая таблица.
- G7. HTML письма — email-safe: табличная вёрстка, инлайн-стили, ширина 600px (как текущий `toHtml`).
  Пользовательский HTML в предпросмотре показывается только в `<iframe sandbox>` без `allow-scripts`.
- G8. Тексты интерфейса — по-русски, в тоне существующего кабинета. Не ломать отчёты «3» и «3а»
  (их бланк PPr2 сохраняется) и существующие письма в `S.MAILINGS`.
- G9. Проверка: в репозитории нет тестов. Каждая задача добавляет Playwright-смоук на Python в `tests/`
  (`python3 tests/<file>.py`; тест сам поднимает `http.server` на свободном порту из корня репозитория,
  открывает страницы в headless Chromium, проверяет поведение и отсутствие `pageerror`/console error,
  печатает `PASS`/`FAIL` и выходит с кодом 0/1). Python Playwright и Chromium установлены на машине.

## Решения

### Отчёты
- **Движок данных** `admin-report-data.js` → `window.AdminReportData`: из `S.EVENTS` (+ зоны/цены из
  `S.TIERS`) генерирует журнал операций `{id, opDate:"YYYY-MM-DD", eventId, eventTitle, eventDate, hall,
  zone, row, seat, price, kind:"sale"|"refund"|"reserve"|"invite", channel, cashier, pay, pk}`, где
  `channel` ∈ «Касса», «Интернет», «Уполномоченный: <имя>», `pay` ∈ «Наличные», «Карта», «СБП»,
  «Пушкинская карта», «Сертификат». API: `ops(filter)`, `events()`, `channels()`, `payTypes()`,
  `sum(rows, key)`, `groupBy(rows, keyFn)`.
- **Виды отчётов** `admin-report-kinds.js` → `window.AdminReportKinds`: архетипы (по мероприятиям,
  по датам операций, по каналам/уполномоченным, по типам оплаты, заполняемость мест, возвраты,
  брони/приглашения, Пушкинская карта, музейные посещения, приказы, мероприятия/репертуар,
  книга операций). Каждый возвращает спецификацию в формате `AdminReportSpecs`
  (`fields`, `columns`, `rows(params)`). Классификатор сопоставляет строку каталога архетипу по ключевым
  словам названия и категории + явная таблица переопределений. `AdminReportSpecs.get(no)` отдаёт ручную
  спецификацию, если она есть, иначе сгенерированную — так открывается любой номер каталога.
- **Страница отчёта**: параметры применяются; выгрузки Word, Excel, CSV, «Печать / PDF»
  (`window.print()` с печатными стилями — печатается только документ).
- **Каталог**: «↓ Выгрузить» скачивает отчёт в Excel с параметрами по умолчанию без перехода;
  «⚙ Настроить» открывает `report.html?no=…&setup=1` (раскрыт выбор столбцов, фокус на первом поле).
- **Бухгалтерия**: «Сформировать отчёт» на `ledger.html` открывает `report.html?no=Б-1` — «Книга
  операций» из `S.LEDGER` с итогами доходов, расходов и сальдо; строка `Б-1` добавляется в каталог.

### Письма
- Письмо получает режим: `letter.mode = "blocks"` (по умолчанию) или `"html"` с `letter.html`.
  В режиме HTML вкладка «Код» — редактор: моноширинный шрифт, Tab вставляет 2 пробела, живой предпросмотр
  рядом (задержка ~300 мс), размер письма, предупреждения линтера (нет табличного каркаса, `<script>`,
  `<link rel=stylesheet>`, `href="#"`, картинки data-URL, ширина > 600px). Переход блоки → HTML —
  «Редактировать как HTML», обратно — «Вернуться к блокам» (HTML-правки теряются); оба с подтверждением
  во встроенном диалоге (не `confirm()`).
- Текст и заголовок: панель форматирования (Ж, К, ссылка, список) с безопасной мини-разметкой
  (`**жирный**`, `_курсив_`, `[текст](https://…)`, строки с `- ` → список); рендер экранирует всё прочее.
  Старые письма без разметки выглядят как раньше.
- Переменные: вставка `{{name}}`, `{{email}}`, `{{event_title}}`, `{{unsubscribe_url}}`; в предпросмотре
  подставляются демо-значения; в отправляемом HTML без `{{unsubscribe_url}}` добавляется строка отписки.
- «Скачать .html» — файл письма. «Тестовая отправка» — встроенный диалог: до 5 адресов с валидацией,
  запись в `letter.tests[] = {to:[…], at:ISO}` + тост. Реальной отправки нет (нет бэкенда) — это прямо
  сказано в диалоге.
- Кнопка без ссылки больше не даёт `href="#"`: в HTML ссылка опускается, в панели — предупреждение.
- **Импорт и экспорт (добавлено 2026-10-27 после слияния):** меню «Импорт ▾» — HTML-файл, вставка
  HTML-кода, шаблон редактора `.json`; «Экспорт ▾» — HTML-файл, копирование HTML, шаблон `.json`.
  Импорт HTML переводит письмо в режим HTML с сохранением блоков; замена непустого письма — с подтверждением.
