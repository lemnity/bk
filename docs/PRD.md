# PRD — сайт продажи билетов и кабинет администратора

Статус: рабочий прототип (статический сайт, без бэкенда). Обновлено: 2026-10-27.
Связанные документы: [architecture.md](architecture.md) · [design.md](design.md) · [rules.md](rules.md) ·
[tasks.md](tasks.md) · [memory.md](memory.md).

## 1. Кратко

Сайт театра с афишей, страницами спектаклей и покупкой билетов с выбором мест на схеме зала, плюс
кабинет администратора: справочники, отчёты, бухгалтерия, email-рассылки, маркетинг. Сейчас это
**кликабельный прототип**: все данные демонстрационные и живут в браузере (localStorage), оплаты,
почты и учёта мест нет. Задача прототипа — согласовать сценарии и интерфейсы до разработки бэкенда.

Публикация: GitHub Pages — https://lemnity.github.io/bk/ (ветка `main`).

## 2. Цели

- Зритель за 3–4 шага находит спектакль, выбирает сеанс и места и оформляет заказ.
- Администратор получает любой отчёт из каталога (~150 номеров) с фильтрами и выгрузкой в Word, Excel,
  CSV, PDF.
- Маркетолог собирает email-письмо в конструкторе или как HTML, проверяет и отправляет тест.
- Единая визуальная система публичной части и кабинета (см. [design.md](design.md)).

## 3. Не входит в объём (сейчас)

- Реальная оплата, эквайринг, фискализация, электронные билеты.
- Серверное хранение, учёт мест и остатков, многопользовательский доступ, роли.
- Реальная отправка писем (тестовая отправка только пишется в журнал письма).
- Реальные продажи в отчётах: данные генерируются детерминированно (см. [architecture.md](architecture.md) §5).

## 4. Пользователи

| Роль | Что делает |
|---|---|
| Зритель | Смотрит афишу и страницы спектаклей, выбирает места, оформляет заказ |
| Администратор / директор по продажам | Ведёт справочники, смотрит консоль и аналитику, строит отчёты |
| Бухгалтер | Книга операций, отчёт Б-1, выгрузки для учёта |
| Маркетолог | Рассылки, аудитории, рефералы, реклама на билетах, счётчики аналитики |

## 5. Ключевые сценарии

### 5.1. Покупка билета (публичная часть)
1. Афиша (`index.html`): карточки спектаклей, фильтр по типу события.
2. «Подробнее» → страница спектакля (`show.html?id=…`): описание, создатели, площадка, фото, встроенный
   план зала. «Купить билет» на афише открывает модальное окно с выбором мест.
3. Выбор даты и времени → места на схеме (тарифы цветом, занятые — штриховкой, до 12 мест) → «Ваш заказ»
   (сервисный сбор 200 ₽/билет, бонус 5%) → оформление (контакты, способ оплаты, согласие) → билет.

### 5.2. Отчёт (кабинет)
1. Каталог (`reports.html`): избранное, категории, поиск; «↓ Выгрузить» — Excel сразу,
   «⚙ Настроить» — форма с выбором столбцов.
2. `report.html?no=…`: параметры (период, мероприятие, канал, тип оплаты) реально фильтруют данные;
   «с» позже «по» — ошибка у поля; пусто — «Нет данных за выбранный период».
3. Выгрузки Word / Excel / CSV / «Печать / PDF» повторяют то, что на экране.
4. Бухгалтерия → «Сформировать отчёт» → «Книга операций» (Б-1): доходы, расходы, сальдо нарастающим итогом.

### 5.3. Email-рассылка (кабинет)
1. `mailings.html` → «Добавить» → `mailing.html`: название, аудитория, отправка, акция, время.
2. Письмо: конструктор блоков (заголовок, текст, кнопка, картинка, разделитель, отступ, HTML, колонки,
   контейнер) или режим HTML-кода с живым предпросмотром и линтером.
3. Форматирование текста (жирный, курсив, ссылка, список), переменные `{{name}}`, `{{email}}`,
   `{{event_title}}`, `{{unsubscribe_url}}`; строка отписки добавляется автоматически.
4. Импорт (HTML-файл, вставка кода, шаблон .json) и экспорт (HTML-файл, копирование, шаблон .json).
5. «Тестовая отправка» на 1–5 адресов (журнал), затем «Сохранить» / «Отправить» (в очередь).
   Правило: не чаще раза в 7 дней на одну аудиторию.

## 6. Страницы

**Публичная часть:** `index.html` (афиша), `show.html` (спектакль), `promo.html` (прежняя промо-страница
«Прощальные гастроли» со схемой зала; в навигации не участвует).

**Кабинет:** `admin.html` (консоль: KPI, финансы, графики, «Задачи на день»), `venues.html`, `halls.html`,
`rental.html`, `actors.html`, `events.html`, `reports.html` + `report.html`, `analytics.html`,
`prices.html`, `ledger.html`, `ticket-ads.html`, `mailings.html` + `mailing.html`, `referrals.html` +
`referral.html`, `audiences.html` + `audience.html`, `integration.html`. Пункты меню без страницы
открываются шаблоном-заглушкой `section.html?s=…`.

## 7. Требования и критерии приёмки (реализовано)

| Область | Критерий |
|---|---|
| Афиша | Все спектакли с будущими показами; фильтр по типу; «Подробнее» → страница; «Купить» → окно мест |
| Покупка | Сеанс → места → заказ → оформление → билет; купленные места становятся занятыми |
| Отчёты | Каждый номер каталога открывается рабочим отчётом; фильтры применяются; экран = выгрузки |
| Бухгалтерия | Б-1 из живой книги операций, корректное сальдо в отфильтрованном периоде |
| Письма | HTML-режим в песочнице; форматирование; переменные; отписка; импорт/экспорт; тестовая отправка |
| Доступность | Видимый фокус, контраст AA, диалоги с ловушкой фокуса, Esc, `prefers-reduced-motion` |
| Качество | 9 Playwright-смоуков в `tests/` проходят (см. [rules.md](rules.md) §4) |
